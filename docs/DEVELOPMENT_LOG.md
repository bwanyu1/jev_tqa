# Diffusion-Jev 開発記録（2026-10-20 〜 10-24）

既存の自己回帰（AR）の視覚言語モデルを、DiffusionGemma 論文（arXiv:2608.00146）の手順で離散拡散モデルに作り変え、Jev 風の「型付き判定モデル」（Choice / Noul / Score を確率付きで答える）に仕立てた記録。何をどの順で作ったか、どこでつまずいて何を学んだかを残す。結果の詳しい数値と図はレポート（`docs/Diffusion-Jev_report.pdf`）にある。

## 1. 結論

- **拡散化は、出力の各部分を同時に決める課題で自己回帰に勝てた。**
  - 数独：完全正解 65.0% vs 4.0%、応答 0.50 秒 vs 8.9 秒（同じデータ・同じ学習量）
  - 1 文に 16 問の判定（穴埋め形式）：正解率 96.3% vs 95.5% で同等、応答 0.55 秒 vs 1.13 秒
  - 判定の確率の正確さ：ECE 0.007 vs 0.021
- **答えが 1 つの判定、長い自由文、日本語では自己回帰の方が良い。**
  - 判定 1,800 問：90.5% vs 91.3%
  - 長い自由文の採点：1.6 点以下 vs 6.8 点（拡散化していない元のモデルとの比較）
  - 日本語の判定（Amazon レビュー）：79.8% vs 81.2%
- 画像は一度も学習していないが、拡散化後も元のモデルから −1.3 ポイント（88.0% → 86.7%）にとどまった。
- 環境は RTX 4060 Ti（16GB）1 枚。バックボーンは Qwen3-VL-4B-Instruct。

## 2. 全体の流れ

```
論文読解・設計
  └─ 実装（拡散化・サンプラー・SFT・RLCD・判定API）→ 小さいモデルでテスト
       └─ バックボーン選定（Qwen3-VL-4B）→ WSL の GPU 環境
            ├─ ① RLCD 版（拡散化と選好データの学習を同時に）……失敗
            ├─ ② 2 段階化：汎用の拡散化（§4）→ Jev 化（§8）……判定 87.5%
            ├─ ③ データ拡充：GPT-OSS で蒸留・ラベル検証・日本語追加
            ├─ ④ 速度と品質の測定、損益分岐点の分析
            ├─ ⑤ 対照実験（同じデータで AR を SFT）……判定では AR が僅差で上
            ├─ ⑥ 拡散向きの課題：数独・多問判定 ……数独で圧勝
            ├─ ⑦ 簡略版 SD·RL ……効果なし
            └─ ⑧ 穴埋め形式の Jev 化 ＋ 公平な比較 ……多問判定の速度と較正で勝ち
```

## 5. 知見

### 拡散化そのもの

1. **変換しただけではデノイズできない。SFT が必須**（論文 §4・図 6 と一致）。
2. **汎用の拡散化と用途別の学習は分ける。** 一度にやると文章を書く力ごと崩れた（RLCD 版）。分けると判定は 53% → 87.5% になった。
3. **SFT だけのモデルはステップ数を多めに。** 論文の N=48 は SD·RL 後の値。SFT だけでは N=48 で繰り返しループが出て、N=192 で解消した（論文 §5・図 10 と一致）。代わりに速度は落ちる。
4. **速さは「推論 1 回で何トークン進めるか（TPF）」で決まる。** 4060 Ti では、拡散の 1 回（106ms）が AR の 1 トークン（50ms）の約 2.1 倍重いので、TPF 2.1 が分岐点になる。キャンバス 1 枚を S ステップで仕上げるなら、出力が約 2.1×(S+1) トークンより長いと拡散が速い。
5. **確率は最初のステップ（完全にノイズの状態）で読む。** 収束後の確率は 0 か 1 に偏る。最初のステップの確率は温度調整なしでもよく較正されていた（ECE 0.007〜0.016）。

### どこで拡散が勝つか

6. **答え同士が強く制約し合う課題では圧勝する**（数独 65% vs 4%）。AR は左上から 1 マスずつ書くので、後のマスの制約を前のマスに反映できない。
7. **答え同士がほぼ独立した判定では勝てない。** 1 問だけなら AR はロジットを読むだけで推論 1 回（0.06 秒）で済む。
8. **判定を明確な穴埋め問題にする。** 値だけを壊して復元する学習と多問データの追加により形式の崩れがなくなり、16 問の全問正解率は 1% → 54% に、応答は 2.48 秒 → 0.55 秒になった。
9. **画像の能力は、テキストだけで拡散化してもほぼ残る**（−1.3 ポイント）。

### 評価の進め方

10. **必ず「同じデータで学習した AR」と比べる。** 「拡散の勝ち」に見えた結果が 2 回、公平な比較で消えた。1 回目は Jev 化 v2 の 87.5%（相手が学習なしの AR だった）。2 回目は穴埋めの多問判定の精度（AR が多問データを見ていなかった）。
11. **自由文の質は採点モデルで、速度と質は同じ問題で測る。** 短い例だけで判断しない。空の例では N=192 でもきれいに見えたが、256 トークンの回答では崩れが目立った。
12. **「JSON を書けなかった」と「答えが間違っていた」は分けて数える。** 汎用モデルの画像評価は、厳密に数えると 24.7%、形式の崩れを許すと 57.0% だった。

### データ

13. **蒸留したラベルは検証する。** GPT-OSS-20B の判定ラベルは 4 問に 1 問が誤りだった。思考を深くして解き直させ、一致したものだけ残すと、120B との一致率が 93.5% になった。
14. **RLCD の選好データは判定モデルには合わなかった。** 露骨な対比で覚えた判断は、人手ラベルの微妙な差には使えない（RLCD 論文の選好モデル 52.4% と同水準）。
15. **キャンバスの空きは終了トークンで埋める。** パディングで埋めると、短い学習で「全部パディング」に崩れた。
16. **途中で切れた回答も使える。** ブロック自己回帰では、回答の先頭の K 枚のキャンバスだけを終了トークンなしで学習すればよい。最初はこれをはじいてしまい、データの 8 割を捨てていた。
17. **日本語はトークナイザが鍵。** Qwen は「単」「効」「値」のような普通の漢字を複数の断片に分ける（漢字・かなの 15.6%）。拡散は断片を同時にばらばらに決めるので文字化けする。Gemma 4 ではほぼ起きない（0.1%）。

### SD·RL

18. **ステップ数がもともと少ない課題では効かない**（数独は 4〜5 回）。
19. **自分の出力で学習を続けると崩れる。** 数独では 30 回で 65.5% → 55.5%。先生を固定する、正則化を入れるなどが必要。

### 環境・実装でつまずいた点

| 症状 | 原因 | 対処 |
| --- | --- | --- |
| `cache.crop(P)` がエラー | transformers v5 で引数が「削除するトークン数（負）」に変わった | `cache.crop(-C)` |
| Gemma 4 で学習経路と推論経路がずれる | スライディングウィンドウ層にカスタムマスクが素通しされる | 層の種類ごとのマスクの dict を渡す |
| Gemma 4 E2B/E4B が使えない | 層ごとの埋め込み（PLE）が `input_ids` 必須で、`inputs_embeds` への足し込みと両立しない | 対象外に。埋め込み層の出力に後から足す方式なら回避できる可能性あり |
| Qwen3.5 / 3.8 などの新しい軽量モデルが使えない | 線形注意や畳み込みとの混成で、マスクによる双方向化ができない | 全層が通常の注意のモデルに限定 |
| Qwen3-VL が `AutoModelForCausalLM` で読めない | 画像テキスト用の Auto クラスにしか登録がない | `AutoModelForImageTextToText` に自動で切り替え |
| vLLM の top-k/top-p で起動失敗 | FlashInfer がカーネルをその場でビルドしようとするが、nvcc がない | `VLLM_USE_FLASHINFER_SAMPLER=0` |
| vLLM で GPT-OSS-20B が 16GB に載らない | 重み 13.8GB ＋ CUDA グラフ | `--enforce-eager --gpu-memory-utilization 0.925 --max-num-batched-tokens 2048` |
| SSH が切れる | `pkill -f` のパターンが、実行中のコマンド自身にも一致した | PID を指定する、`[v]llm` のような自己一致しない正規表現を使う |
| 実行中のキューを差し替えると壊れる | bash はスクリプトを逐次読みする | 実行中のファイルは編集せず、別の待機スクリプトで順番を変える |
| SSH が止まる | Tailscale SSH の check モードで定期的に再認証を求められる | 表示される URL で承認する |
| Groq が 1 日 200 件程度で止まる | 無料枠の 1 日 20 万トークン制限 | 量は手元の GPU で作り、Groq は品質用に使う |
| OpenCode の無料モデルは使えない | 規約で、出力のプログラムによる取り出しと競合モデル開発が禁止 | データ作りには使わない |

## 6. 再現手順（WSL、RTX 4060 Ti）

```bash
# 環境
uv venv -p 3.11 .venv && uv pip install -p .venv torch transformers peft accelerate pytest av torchvision pillow pyarrow requests
uv venv -p 3.12 .venv-vllm && uv pip install -p .venv-vllm vllm pyarrow
.venv/bin/python -m pytest -q tests

# 1. 汎用の拡散化（自己蒸留 → §4 の SFT）
scripts/run_general.sh          # v1 / v2
scripts/pipeline_ja.sh          # 日本語を足して v3

# 2. 判定データ
.venv/bin/python -m djev.decision_data --out data/decisions
.venv/bin/python -m djev.infill build-many --out data/many_questions_train.jsonl

# 3. 穴埋め形式の Jev 化と評価（AR の対照実験を含む）
scripts/pipeline_infill.sh
scripts/after_infill_ar_v5.sh
scripts/after_v5_image.sh

# 4. 数独
scripts/parallel_tasks.sh       # 多問判定と数独（拡散・AR）
```

主なチェックポイント（`runs/`）：`general_v3`（汎用の拡散化）、`jev_infill`（穴埋め形式の Jev 化）、`ar_sft_v5`（対照実験）、`sudoku_diffusion`、`sudoku_ar`。

## 7. 次の候補

1. **日本語の改善**：まず学習不要のサンプラーの工夫（文字の断片がつながらない箇所を埋め直させる）。根本的には、日本語のトークナイザが良く、動画も扱える Gemma 4 E4B で同じ手順をやり直す（PLE への対処が必要）。

本物の Jev とは比較しない。Jev は判定専用に作られたモデルで、汎用モデルを拡散化した今回のモデルとは性質が違う。

## 9. 説明資料の追補（2026-10-25）

構造化出力とJevの相性という背景を明示し、[手法・データ・実測例](Diffusion-Jev_methods.md)を追加。拡散化3節・Jev化4節で、式、学習データの内訳、投入順序、最終128トークン設定、first読み出しと反復時間の違いを記載した。穴埋め化と多問データ追加の効果は分離できていない点も明示。保存済み自由文GIF、画像判定の成功・形式エラー・誤答を掲載し、説明用の例と実測例を分けた。今回の作業では学習・推論の再実行はしていない。

画像例の対応を再確認。ヒョウは類似した適応を持つ別の動物を問う問題、街角は左奥の銀行広告を読む問題。スライド18・19へ日本語訳・着目箇所を追加し、19は広告を拡大した。A-OKVQA原データの選択肢・正解・解説と一致することを確認。

画像理解の実例を再選定。ヒョウ・広告の2例から、保存例2（乗馬のあぶみ）・5（磁石の距離比較）へスライド18・19を差し替えた。画像なし対照は未実施で、画像付き600問の正解率だけでは画像の寄与を確定できない旨を追補・レポートに記載。新規推論は実行していない。

発表の結果を最終の `jev_infill` と `ar_sft_v5` に限定。数独専用・汎用自由文・途中版の比較は発表から除外し、旧レポートを実験アーカイブへ保存。最終版の画像個別ログはGPU環境への接続失敗で未回収。旧版の個別出力は流用しない。

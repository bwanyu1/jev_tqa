# 動画の再試用：作業フェーズの定義

2026年10月25日。前回の「机／把持／機械付近」という位置・状態の混在を見直し、作業動作として再試用する。同じ最終2モデル・同じ動画を使い、追加学習はしない。

## 判定対象と時間単位

対象は小さな淡色のコーヒーカプセルと機械の蓋。それらに関与する把持器の動作を判定し、透明なカップだけを扱う動作は除外する。2秒区間内で、最も長く見える動作を選ぶ。重要そうな瞬間を区間全体のラベルにしない。同率・大半が見えない場合は不明。蓋の動作と対象物の動作が同時なら蓋を優先する。この優先規則も暫定定義であり、将来的には両手・対象物別の並列ラベルが望ましい。

| 値 | 動作 | 映像上の条件・境界 |
| --- | --- | --- |
| 1 | 物体への接近 | 空の把持器がカプセルへ近づく。指が閉じ始めたら終了。近いだけでは該当しない |
| 2 | 把持 | カプセルを囲む指が閉じる動作。閉じ終わり、対象物が一緒に動き始めるまで。保持状態とは区別 |
| 3 | 把持移動・設置先への接近 | カプセルを保持し、把持器と一緒に移動。挿入・下ろす動作が始まるまで。保持して静止なら動作なし |
| 4 | 開ける | 機械の蓋が閉→開へ実際に動く。開いた蓋が見えるだけでは該当しない |
| 5 | 設置 | カプセルを目的地へ挿入・下ろす、または指を開き支持された対象物を残して離れる。今回の定義では解放前の挿入も含む |
| 6 | 閉める | 機械の蓋が開→閉へ実際に動く。閉じた蓋が見えるだけでは該当しない |
| 7 | 動作なし | 関連する動きが見えない。保持したままの静止を含む。遮蔽は根拠にしない |
| 8 | その他の動作 | 1〜7に入らないが明確に見える関連動作。例：空の把持器の後退 |
| 9 | 不明 | 遮蔽・対象不明・静止画・動作の競合などで確定できない |

選択肢の順は作業手順を指示しない。抜け・繰り返し・順序の違いを許す。逆再生でも元の作業意図を推測せず、見える向きの動作を判定する。静止画だけでは過去区間と全体の移動方向を不明にする。

## 比較設計

正順12.8秒・逆順・最終静止画について、同じ9択を「ラベル名だけ」と「上の詳細定義あり」で比較する（6条件）。共通の対象指定・静止画で推測しない指示は両方に入れる。追加で、元動画の全22秒を詳細定義で試す（1条件）。各モデル7条件、計14回。

前回は位置の時点判定、今回は動作の区間判定であり、前回と今回の正解率差を定義改善の効果にはできない。今回の同一9択・定義文の有無で比較する。1区間を単一ラベルにするため、短い把持・開閉イベントが区間の代表動作に選ばれない場合がある。開閉を答えなかっただけで見落としとはしない。

元の全22秒には対象外のカップの移動も含まれる。長尺化では参照フレームが上限32枚となるため、12.8秒の試用と時間解像度も異なる。独立した人手正解ラベルは未作成なので、出力の変化と目視で分かる矛盾を確認し、正解率は算出しない。

## 拡散Jevの初回出力

位置ラベルから動作ラベルに変えた結果を、前回と同じ意味の数字として読まないこと。以下は今回の9択の番号。

| 条件 | 0–2 / 2–4 / 4–6 / 6–8 / 8–10 / 10–12秒 | 全体の方向 |
| --- | --- | --- |
| 名称のみ・正順 | 1 / 2 / 2 / 2 / 1 / 1 | 机→機械 |
| 詳細定義・正順 | 1 / 2 / 2 / 3 / 1 / 1 | 机→機械 |
| 名称のみ・逆順 | 2 / 2 / 2 / 3 / 3 / 1 | 机→機械 |
| 詳細定義・逆順 | 2 / 2 / 2 / 3 / 3 / 1 | 机→機械 |
| 名称のみ・静止画 | 1 / 2 / 3 / 3 / 3 / 3 | 机→機械 |
| 詳細定義・静止画 | 1 / 2 / 3 / 3 / 3 / 3 | 机→機械 |

詳細定義で変わったのは正順6〜8秒の1区間（把持→把持移動）。目視でこの区間は保持した移動があるため、変更は定義に沿う方向。ただし正順の8〜12秒を空の把持器による「接近」と答え、4〜6秒にも閉じるイベントである「把持」を継続して答えている。対象物が保持されていることと、把持するイベントを十分に区別できていない。

逆順の移動方向は詳細定義でも机→機械のまま（候補内確率91.0%）。静止画の各区間も不明にならず、方向は机→機械（91.1%）になった。名称のみの静止画方向は77.8%なので、定義を足せば推測が抑えられるとも言えない。候補内確率は正解の信頼度として校正した値ではない。

全22秒版の拡散firstは `1,2,2,2,2,1,1,7,1,3,1`。カップを扱う後半にもカプセルへの接近・把持移動を出しており、対象物の切り分けにも課題がある。開閉が0件でも、短いイベントが区間の代表に選ばれない設計なので、これだけで開閉を見落としたと判定しない。

ARの正順は、名称だけで `1,2,3,1,1,1`、詳細定義で `1,2,3,3,3,3`。後半3区間が空の把持器の接近から保持した移動に変わり、保持と接近の区別には改善の兆候がある。ただし10〜12秒の挿入・設置も把持移動と答えており、定義した境界を十分には反映できていない。ARは逆順でも方向を机→機械と答え、静止画の全区間を動作なしとした。不明と動作なしの区別も未解決。

**結論：今回の詳細定義は出力に影響したが、安定した改善は確認できない。特に拡散は正順1区間だけが変わり、逆順と静止画の最大候補は変わらなかった。ARの方が定義の影響が大きかったが、正しく定義を適用できたとは言えない。** 単一動画・各条件1回、正解ラベル未整備なので、一般的なモデル能力差や定義改善の効果量は結論づけない。

「定義は重要」という仮説を否定する結果ではない。一方、定義を文章で詳しく渡すだけで十分とも言えない。次は次の順で切り分ける。

1. **状態とイベントを別の穴にする。** 保持の有無、移動、蓋の状態を観察項目とし、把持開始・解放・開閉をイベントとして付ける。単一9択で短いイベントを消さない。
2. **対象・手・区間を固定する。** 参照画像やクロップでカプセルを指定し、手と対象物別にラベルを持つ。今回の蓋優先規則も、人の用途に合わせて再設計する。
3. **正例・境界例・非該当例を用意する。** 定義が人同士で一致するか確認した上で、元バックボーン、最終AR、拡散の定義追従と少量学習の効果を比較する。
4. **選択肢の番号依存を確認する。** 今回の出力が1〜3へ偏った原因は未確定。番号を入れ替えた対照などで、意味・候補位置・典型的手順への依存を切り分ける。

今回の試行は定義文の有無の比較で、上の追加検証は未実施。モデル重み・通常API・サンプラーの変更なし。動画試用スクリプトのテンプレート長チェックを通し、全14件がエラーなしで完了。動画では抽出時刻とグリッドを生ログに保存し、ARテキスト経路の既存実装との最大確率差0.0を再確認した。

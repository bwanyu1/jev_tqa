# Diffusion-Jev 最終モデル比較レポート

2026年10月25日更新

発表スライドは本編42枚＋補足13枚（全55枚）。章末の結論は仕組み6枚目、比較12枚目、実務20枚目、複数画像27枚目、動画35枚目。各例の処理時間は起動を除いて記載。詳しい理論・学習データは補足44〜50枚目。最新の掲載位置・構成評価は[スライド見直し記録](Diffusion-Jev_slides_review.md)に記載。

## 比較するモデル

結果は、完成した拡散JevとARの2モデルだけを掲載する。

| 項目 | 拡散Jev | AR |
| --- | --- | --- |
| チェックポイント | `runs/jev_infill` | `runs/ar_sft_v5` |
| バックボーン | Qwen3-VL-4B-Instruct | 同じ |
| 判定SFTデータ | 判定＋多問の約65,000行 | 同じ |
| 判定SFT | 6,000ステップ | 6,000ステップ |
| テキスト判定 | 回答テンプレートの穴を並列更新 | 同じ穴を左から順に埋める |
| 先行学習 | 汎用拡散化v3から開始 | 元のモデルから判定SFT |

判定SFTのデータと歩数は揃えているが、拡散化の先行学習を含めた総学習量は等しくない。学習・評価はRTX 4060 Ti（16GB）1枚で行った。

## 背景と手法

出発点は、DiffusionGemmaが構造化出力を少ない反復で完成できるなら、型付きの複数判定を確率付きで返すJevと相性がよいのではないか、という仮説。

既存のQwenを汎用の離散拡散モデルへ変換し、その後にChoice / Noul / Scoreの判定を学習した。最終版は、値の位置だけを壊して復元する**明確な穴埋め問題**として学習する。推論でも既知のJSON部分を維持し、複数の穴を並列に更新する。

拡散化3節・Jev化4節の理論、データと設定は[手法の詳細](Diffusion-Jev_methods.md)を参照。

## 最終結果：精度と確率

| 指標 | 拡散Jev | AR |
| --- | --- | --- |
| 判定の正解率（評価1,800行） | 90.5% | **91.3%** |
| ECE（小さいほど良い） | **0.007** | 0.021 |
| NLL（小さいほど良い） | **0.25** | 0.31 |
| 画像付き問題の正解率（600問） | 86.7% | **90.0%** |
| 日本語の判定（Amazonレビュー） | 79.8% | **81.2%** |

拡散Jevは較正が良く、正解率はARが上だった。ECEは確信度と実際の正答頻度のずれ、NLLは正解へ割り当てた確率の評価である。

テキスト評価は公開9種類の各200行。同じ行に複数の問いがあるので、1,800行と判定質問数は区別する。画像はScienceQA 300問＋A-OKVQA 300問で、画像を追加学習には使っていない。ただし画像付き問題には文章だけでも解ける問題があり、画像なし対照は未実施。正解率だけで視覚情報の寄与は確定できない。

## 最終結果：質問数と速度

GoEmotionsの同じコメントへk個の問いを付け、各kにつき100件。時間は中央値、回数は1件あたりの平均。

| 質問数 | 拡散Jev：正解率 / 全問正解率 / 秒 / 推論回数 | AR：正解率 / 全問正解率 / 秒 / 推論回数 |
| --- | --- | --- |
| 1 | 84.0% / 84% / 0.21 / 2.2 | 87.0% / 87% / 0.06 / 1 |
| 4 | 90.5% / 74% / 0.33 / 3.5 | 87.3% / 69% / 0.27 / 4 |
| 8 | 91.0% / 60% / 0.40 / 4.3 | 92.6% / 65% / 0.53 / 8 |
| 16 | 96.3% / 54% / 0.55 / 5.7 | 95.5% / 60% / 1.13 / 16 |

16問では拡散Jevが約2倍速い。質問ごとの正解率は近いが、全16問が正しい割合はARが上。1問ではARの方が速い。

拡散の答えと確率は最初の予測（first）を使用し、時間は反復停止までを計測している。firstだけで終了する実装の速度は未測定であり、反復がAPIの正解率を上げたという結果ではない。

## 画像読み取り：最終2モデルの実際の入出力

最終評価ログ `logs/img_jev_infill.jsonl`・`logs/img_ar_sft_v5.jsonl` と入力 `data/image_eval.jsonl` をGPU環境から回収し、600行すべての正解ラベルを照合した。全体正解率も86.7%・90.0%と再確認。新たな推論は行っていない。

| 入力と問い | 正解 | 拡散Jevの実際の答え（候補内確率、first） | ARの実際の答え（候補内確率） |
| --- | --- | --- | --- |
| 乗馬写真：男性の足を支えるものは？（蹄鉄／スパイク靴／靴／あぶみ） | 4：あぶみ | **4：あぶみ（93.1%）** | **4：あぶみ（99.7%）** |
| 磁石の図：各組の磁力は？（同じ／Pair 2が弱い／Pair 1が弱い） | 3：Pair 1が弱い | **3：Pair 1が弱い（59.2%）** | **3：Pair 1が弱い（95.3%）** |

写真では足元の道具を認識し、磁石の図では2インチ対1インチの間隔を読む。表示用の問いは日本語訳、モデルへの実際の問いは英語。磁石の文脈は「各組は互いに影響しない、同じ材質」で、距離は図にのみ記されている。2例とも最終版では正解している。個別例の成功は全体正解率や画像の寄与を証明するものではない。

入力・生の確率分布・チェックポイント・評価行番号を[最終版の個別出力](image_examples_final.json)に保存した。対応するスライドは16・17枚目。途中版の出力は掲載していない。

## 業務を想定した試用

最終の拡散Jevを実際に動かし、今回書いた問い合わせ・レビュー9件で使い勝手を確認した。日本語の二重請求から担当・至急・返金要求など6項目を0.411秒で取り出し、曖昧な依頼では情報不足を選べた。一方、明確な英語の当日期限でも至急52.5%と迷い、確率の運用閾値には検証が必要と感じた。読み込み153.7秒、初回5.648秒、以後0.228〜0.506秒。ベンチマークではなく、架空の業務文を使った小規模な手動試用。[実際の入力・返り値と使用感](Diffusion-Jev_practical_tryout.md)を参照。

## 画面操作・画像付き点検への試用

最終拡散Jevを、ブラウザで描画したフォーム画像と点検用図版で17回使用した。エラー表示や送信成功は読めたが、未入力・無効ボタンと正しく判定しながら「次は送信」と答えた例があった。点検図版では赤ランプに反応した一方、ボルト欠落・配線抜け・遮蔽を見落として高い確率で合格にした。局所拡大の4件でも区別は安定しなかった。

画面状態の整理には使い道がありそうだが、操作前に必須項目・ボタン状態・送信中状態をコードで検証する必要がある。点検の合格判定は、今回の図版試用では任せにくい。実設備写真・実際のクリック操作は未試用。[画像と実際の出力を並べた記録](Diffusion-Jev_visual_practical.md)を参照。

## 複数画像を使った参照照合

最終拡散Jevへ2枚または6枚の画像を順番付きで渡し、計23回試した。2枚の色・模様の違いと、参照写真の切り出しが全体写真にあるかは答えられた。6枚から同じ写真を選ぶ例も正解した。一方、似たマグカップの6枚一括選択は不安定で、対象がない場面にも「ある」と答えた。

同じ5候補を参照＋候補の2枚ずつに分けると、今回は5件とも想定どおりで、一致候補の「一致」は59.9%。現状は2枚照合を繰り返し、該当なし・複数一致・保留を後段で扱う構成を検討したい。同じ写真の再提示や同じ見た目と、別角度で撮った同じ個体の照合は区別する。[画像と実際の出力、入力JSONの例](Diffusion-Jev_multi_image_practical.md)を参照。

## 今後の研究課題：能力・学習・定義と動画

重要な仮説を、元モデルの能力と課題への追加学習の不足、および何を正解とするかの定義に整理する。今回の追加学習はテキストで、画像照合や動画アノテーションを直接学習していない。失敗原因は未確定なので、同じ入力で元の能力・AR対照・拡散を補助的に比較し、定義を固定した少量SFTの前後でも切り分けたい。

元からの日本語・トークナイザ改善と、汎用自由文のSD·RLは継続課題として残す。文字断片の再推定、日本語向き基盤の検討、先生を固定・正則化したSD·RLで、同じ問題の品質と反復回数を確認する。実務試用の課題でこれらを置き換えない。

動画は、全編を文脈として参照し、各時間窓の状態ラベルをまとめて穴埋めする構成が仮説として有望。並列性は主に出力ラベルの更新側で、動画デコードや映像特徴の計算は別に測る。ARも同じ動画全体を参照する条件で比べ、窓数を増やしたときの一貫性と速度を確認し、現行のfirstと停止時のfinalの読み出しも比較する。

フィジカルAIの教師データ候補作成を想定し、接触候補・持上げ・運搬・解放・落下・不明の基準と、参照物・成功条件を先に決める。人が付けたラベルと時間境界へ照合し、単フレーム・逆順動画も対照にする。実動画の最小試用は下記に記録した。これらの広範なアノテーション評価は未実施。[研究課題と動画アノテーションの検証計画](Diffusion-Jev_future_work.md)に詳述した。

## 実務構成の課題（試用で確認）

問い合わせ振り分けと返品受付を応用先として、最終拡散Jevを追加24回使用した。復旧済みの障害を現在も全停止と判定し、架空の30日期限を31日経過した返品も96.1%で可能と判断した。長い項目名の16問では回答枠209トークンが128を超え、CUDAエラーになった。

| 優先度 | 今後の課題 | 実務上の目的 |
| --- | --- | --- |
| P0 | 日付計算・期限・例外条件をコードで検証し、モデルの属性判定と最終承認を分ける | 不要な緊急対応や受付可否の誤りを止める |
| P0 | 回答枠長を入口で検証し、外部項目名を短い内部IDへ変換。超過時は分割または明確に拒否 | 1件の長い要求でGPUワーカーを壊さない |
| P1 | 現在・過去・引用・未確認を区別し、保留と複数担当を型へ追加 | 引き継ぎ漏れと、可能性の確定事実化を防ぐ |
| P1 | 候補順・質問順・乱数・業務別の確率と保留基準を切り分ける | 同じ意味の依頼を安定して扱う |
| P2 | 常駐運用、ルール・スキーマの版管理、判定と採否の監査記録 | 起動待ちと誤判断の原因を追えるようにする |

31日期限外は経過日数を追記すると不可97.2%へ改善したが、復旧済み障害と開封免除の誤りは英語でも残った。単に日本語データを増やすだけの課題ではない。まず受付担当者の補助として使い、規則検証と保留を含む運用を作るのが現状の提案。[応用先から考えた実務上の課題・実際の入出力](Diffusion-Jev_operational_findings.md)を参照。

画像あり／なしの対照評価も継続課題。返品写真・明細・配送票の照合への応用は、今回まだ試していない。

実装・試行錯誤の履歴は[開発記録](DEVELOPMENT_LOG.md)。旧実験の数値は[実験アーカイブ](Diffusion-Jev_experiments_archive.md)へ分離した。


## 実動画による最小試用

実ロボットのカプセル運搬動画12.8秒を、最終拡散とARで各6条件試した。正順・逆順・最終静止画と、3/6/12時刻への位置ラベル付けを比較。動画プロセッサが25フレームを参照したことを確認した。

正順6時刻の拡散firstは「机→把持→把持→把持→機械付近→機械付近」と、大きな状態変化を拾った。ただし両モデルとも逆順の方向を「机→機械」と誤り、静止画からも過去の各時刻を回答した。拡散finalでは初回より状態が崩れる例があり、今回の全条件で合計時間はARより長かった。単一動画・各条件1回の試用なので、一般的な性能差の結論ではない。

**動画入力と構造化出力の接続は確認できたが、そのまま教師ラベルに使うにはネガティブな結果。** 追加学習とラベル定義を切り分け、時間順序・不明判定・反復の価値を検証する必要がある。[動画・実出力・時間と再現記録](Diffusion-Jev_video_practical.md)。動画の本編は28〜35枚目。反復・全22秒・全体の時間一覧は補足52〜54枚目に掲載。


### 作業フェーズの詳細定義で再試用

位置ラベルを接近・把持・把持移動・開ける・設置・閉める等の9択へ変更し、同じ選択肢で名称のみ／詳細定義を比較した。最終拡散とAR各7条件、計14回。拡散の正順は6区間中1区間、ARは3区間の最大候補が変わったが、逆順方向の誤判定と静止画での不明判定は解決しなかった。定義は出力に影響するが、文章を詳しくするだけで十分とは確認できない。[定義・比較条件・実出力](Diffusion-Jev_video_phase_definitions.md)。前回の位置ラベル試用とは課題が違うため、正解率の改善としては比較しない。
